# 发布

## 分支

- `main` 只收**验过的**提交；实验性改动留在工作分支，验完再合。
- 首次推送即建立 `main`，之后每个可发版提交都应有可复现的构建记录。

## 版本与 tag

tag 形如 `v1.3.0+engine.0.2.1-rc.2`，即「壳版本 + 引擎版本」，两边一眼能对上。
ds-bot 的 commit 记在 `versions.env` 与 Release 说明里。

## 产物去哪

- **APK 走 GitHub Release 附件**，不进 Git（`.gitignore` 已挡 `*.apk`）。
- `runtime.zip` / `ds-bot.zip` 不进 Git，由 `scripts/build-apk.sh` 现场生成。
- Release 说明里至少写：壳版本、引擎版本+integrity、ds-bot commit、APK 的 sha256。

## 推送纪律

1. 推前扫密钥（`ghp_` / `sk-` / `Bearer` / 私钥 / `.env`）；
2. 只推当前分支，被拒或异常立刻停手；
3. **绝不 force push**；
4. 推送前列出将要推的提交，确认后再推。
