# 补丁：全部落在 runtime/，唯一来源是 collect-termux-runtime.sh

`assets/runtime.zip` 不是上游原样产物。它 = Termux 基础层 + 锁定的引擎版本 + 一组
安卓兼容补丁。**补丁清单不在这里抄**——抄一份就会与脚本不同步，读
`runtime/collect-termux-runtime.sh` 的注释即可（每段都写了"为什么、不打会怎样、幂等做法"）。

## 打补丁的顺序（脚本已固化）

```
整目录替换 lib/node_modules（不合并旧树，避免版本混装）
→ 回填包级补丁（koffi 惰性桩 / node-pty shim / ripgrep-android-arm64）
→ 修剪 *.md / *.map / *.d.ts（LICENSE 保留）
→ 代码级补丁（flock / apiproxy / webview-polyfill / attachment-local /
   require-builtin 回退 / rgPath 前缀改写 / collapsedWidth=0）
→ 真起引擎自检（端口探通 + rg 链路）
→ dedupe → rezip → curl wrapper → verify-runtime-abi
```

## 升级引擎时必须做的两件判断

1. 脚本跑完有没有 `WARN`：`WARN` 不一定是错（包被上游移除、补丁目标不存在都算），
   但每条都要解释清楚并把结论补进脚本该段注释。
2. 两道硬门槛：**端口探通** + **文件搜索可用**（rg 是 arm64 且能执行）。缺一不可。

## 本机两个环境坑

- 存储是 FUSE，**不允许建符号链接**：从 npm 树复制 `node_modules` 必须 `cp -rL`。
- `/storage/emulated/0` 是 **noexec**：引擎自检要在 `$HOME`（内部存储）里跑。
